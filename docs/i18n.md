# JalSaathi translations

The browser loads the six locale dictionaries in `static/i18n/` before
`static/i18n.js`. Keep the initial supported locale set in sync with
`static/profile-store.js`: English (`en`), Telugu (`te`), Hindi (`hi`),
Kannada (`kn`), Tamil (`ta`), and Malayalam (`ml`).

Use stable, domain-specific keys for new interface strings (for example,
`weather.humidity`). The `legacy.*` keys preserve entries migrated from the
previous phrase-based catalog; avoid adding new `legacy.*` keys. Keep each
locale's keys in parity and do not put farmer-entered names, IDs, sensor
readings, or other runtime values in locale resources.

Run the repository localization check after updating strings or page shells:

```powershell
node scripts/i18n-check.cjs
node --test tests_js/i18n.test.cjs
```

The checker verifies the exact six-resource set, duplicate and missing keys,
page references to translation keys, locale-script load order, and literal
HTML phrases missing from the current catalog. Its phrase scan excludes
client-generated text and does not assess translation quality. Existing
translations were migrated from the application's prior dictionary.

Fixed UI text uses the local catalog; Sarvam is not a fallback for unlisted
fixed strings. Apply `data-i18n-remote` only to explicitly approved dynamic
text that may be translated at runtime. Keep farmer-entered data, sensor
readings, identifiers, and numeric values outside that marker.

The checker validates structure, not linguistic accuracy. New translations
should be reviewed by fluent speakers before they are described as verified.
